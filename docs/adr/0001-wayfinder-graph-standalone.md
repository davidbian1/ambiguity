# Wayfinder Graph as a standalone, JSON-backed reimplementation

The `/wayfinder` skill's decision-charting workflow (map/ticket/frontier/fog) is being reimplemented as a LangGraph state graph, with the Claude Agent SDK powering per-ticket resolution. We considered folding this into `src/ambiguity` (same repo, same problem shape: clarifying something under ambiguity) or having it read/write the skill's own GitHub-Issues-backed maps so the two engines could interoperate on the same charts. We rejected both: it lives in its own package (`src/wayfinder_graph/`, reusing only low-level utilities like tracing and JSON parsing from `src/ambiguity`), and its chart/ticket state is plain JSON, entirely separate from the skill's GitHub Issues. A ticket resolved by one system is invisible to the other.

This keeps the new system's storage and domain model simple (no GitHub API, no issue-dependency graph, no shared-state races between two independent engines editing the same issue), at the cost of the two engines never being interchangeable on the same piece of work — picking one is a one-way door for that chart. Not a shared domain model with the ambiguity clarifier either: ticket resolution and spec-interpretation-scoring are different enough problems that forcing one state shape on both would strain both models (see `CONTEXT-MAP.md`).
